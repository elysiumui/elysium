# Persistent authored scene lighting

The old Rendering > Add Light commands appended to an in-memory list that the shared scene renderer never consumed. They now use persistent `AppWindow.scene_lighting`, shared with the native Lights editor and public Aether commands. Existing projects default to studio lighting, retaining their previous appearance. Adding a light enables authored scene lighting; Studio/Scene switches modes while preserving the authored list.

## Data and public authoring

The v1 lighting document contains `schema_version: 1`, boolean `enabled`, monotonic `next_id`, linear RGB `ambient` (0–1), and up to 32 lights with stable `lN` IDs. Each light contains `name`, `type` (sun/point/area), boolean `enabled`, meter-space `position`, XYZ-degree `rotation`, linear RGB `color` (0–1), nonnegative `power`, and positive square-side `size`. Numeric inputs must be finite and within ±1,000,000; power/size upper bounds are 1,000,000. Invalid edits, missing IDs, duplicate IDs and over-limit lists fail before replacing the document. Removing a light never reuses its ID.

Commands: `scene.lighting_get()`, `scene.light_add(values)`, `scene.light_update(light_id, values)`, `scene.light_remove(light_id)`, `scene.lighting_set(enabled?, ambient?)`. Native Lights provides Previous/Next, Add Sun/Point/Area, named numeric fields, Apply, Enable/Disable, Remove, Studio/Scene and Apply ambient. Changes enter document history; fields reject invalid input without creating history. Scene mode, lights and ambient survive Undo/Redo, project save/reopening and native desktop export.

## Render contract

Coordinates are right-handed Y-up meters. Sun and area emission follows local −Y after `Rz Ry Rx` XYZ rotation; a zero-rotation area lies in local XZ. Point lights are ideal isotropic sources with zero radius. Sun lights have zero angular extent. Sun power is irradiance perpendicular to its direction; point power is total isotropic flux, integrated as `power/(4πr²)`. A square area emits only into its forward hemisphere with normalized total flux: its radiance is `power/(π × area)`. The renderer integrates the square with a fixed 4×4 midpoint quadrature, weighted by emitter cosine and inverse-square distance. It casts BVH shadow rays; blockers behind finite emitters do not occlude them. Preview and path tracing share this direct-light function. Scene mode replaces studio direct/ambient lighting, using the explicit uniform ambient color instead. The solid/checker modeling views stay independent of material illumination.

This is deterministic preview area integration, not converged soft-shadow or image-level Blender parity. Other emitter shapes/radii/sun angles, light parenting/animation, Layout/snapshot consistency and matched rendered reference images remain open. The physical power distinction is documented in the [Blender light manual](https://docs.blender.org/manual/en/latest/render/lights/light_object.html); this checkpoint compares authored parameters, not Blender radiometric output.

## Independent GUI/API/Blender fixture

Start from separate GUI and Aether copies of the material-image cube with its existing Hull/Red slots and top-face projected color image. In native Lights add Sun (power 3), Point (100), Area (100, size 2). All use white color, location (0,3,0), zero XYZ rotation, enabled, and zero ambient. Disabling the sun in the initially sun-only scene visibly makes the object black; native Undo restores illumination. After all three additions, Undo removes only Area; Redo/Save/Quit/clean reopening restores the exact final light/material/source state. Independent public commands create the same three lights and match exactly.

In Blender, open the separately authored material-image cube. Add Sun, Point and Area through operator search, move each by G Z 3. Set Sun strength 3 and angle 0; Point power 100 and radius 0; Area power 100, Square, size 2. Normalize remains enabled. Blender Z-up converts to native (x,z,−y), making the positions and emission directions exact. Read-only extraction of the saved .blend confirms every matching field, original mesh geometry, oriented faces, edges, material assignments, shading and top-face UVs (maximum UV difference 5.960464477539063e-8).

Native Export App uses a fresh folder, no close object, size 128, scale 1, end frame 0, hold 0. The actual export contains exact lights, materials and editable source; its nonempty frame differs from the studio baseline. All 14 bounded matrix checks pass. 538 relevant framework and 275 Designer tests pass, including physical falloff, sun rotation, area one-sidedness/far-field flux, all three light types' shadow blockers, enabled/disabled behavior in preview/path tracing, atomic validation, history and saved native export. Broader light/render-family acceptance is still required.
